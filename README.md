## **Персистентность чатов** 📦

### Формат хранения истории сообщений

При запуске сервера в корневой папке ```Project_messenger``` создается каталог ```database```


```database``` - это список всех комнат с их историями сообщений. Например, при создании комнаты с именем ```chat```
в папке создастся файл ```chat.txt```. Каждое сообщение в файле хранится в следующем формате:

```c
seconds message [hash]
```

```
seconds - секунды с 1970 года
message - сообщение от клиента ( строка )
hash - уникально целое число, которое сопоставляется каждому сообщению в истории
```

Пример:
```c
1776593438 hello [210714636441]
1776593576 world [210732791149]
1776593600 how are you? [15227816740892963271]
...
```

### Хеширование 🔐

Правило сопоставления каждой строке уникального числа реализуется с помощью алгоритма ```DJB2```

```c
unsigned long hash( const char* string ){
    assert( string );

    unsigned long hash = 5381;
    int c;
    while( ( c = *string++ ) ){
        hash = ( (hash << 5 ) + hash ) + c;
    }
    return hash;
}
```

### Протокол передачи файлов 📩

При нажатии клавиши ```F9``` открывается окно для ввода полного пути файла, который пользователь хочет отправить.
После ввода имени файла и пути к нему, отправитель подключается к новому каналу, предназначенному для передачи файлов.
Данный канал работает на порту 27011. Далее взаимодействие отправителя и сервера выстраивается следующим образом:

1) Сразу после подключения к файловому каналу клиент отправляет команду:
```
/store <имя файла> <размер файла>
```

2) Сервер видит, что к порту 27011 подключился отправитель, и генерирует ```transfer_id```
```
/sender_ID <transfer_id>
```
Transfer_id генерируется следующим образом: к строке ```<имя_файла>_<количество секунд в данный момент времени>```
применяется хеш функция. Результат хеш фукнции и есть transfer_id.

3) Клиент, получив transfer_id, начинает передавать содержимое файла чанками по 8КБ
```
/chunk <transfer_id> <offset> <size> <chunk>
```
>❗Если размер файла меньше 8КБ, то отправиться столько байт, сколько занимает сам файл

4) На стороне сервера есть папка ```Trasnfers```, в которую сохраняются все полученные файлы.
Имя файла генерируется следующим образом: ```<transfer_id>.<разрешение>```.
При успешном сохранении чанка отправителю посылается команда:
```
/ok <transfer_id> <new_offset>
```

5) При завершении отправки файла, отправитель отключается от файлового канала и рассылает всем участникам текущей комнаты команду:
```
/recipients_ID <transfer_id> <file_name>
```

6) При соглашении о скачивании файла со стороны пользователя, серверу отправляется команда:
```
/retrieve <transfer_id>
```

7) Сервер, получив transfer_id от получателя, находит файл в своей папке и начинает отправку чанками:
```
/chunk <transfer_id> <offset> <size> <chunk>
```

8) Клиент, получив чанк от сервера, отправляет команду об успешном сохранении данных
```
/ok <transfer_id> <new_offset>
```

9) После отправки всего содержимого файла сервер отправляет команду:
```
/close <transfer_id>
```

10) Отправитель, получив команду о завершени отправки, отключается от файлового канала.

## **ИИ - Классификатор** 🔢

Классификатор - это модель, способная по черно - белой картинке с цифрой определить, что эта за цифр.
Обучение сети осуществлялось на основе базы картионок Mnist (60.000 штук), проверка корректности обучения -
на специальных картинках для тестов (10.000 штук). На тестовом наборе нейронная сеть показала результат ```9277``` правильных ответов из
```10.000``` тысяч ```(ошибка 7%)```.


Архитектура слоев нейронной сети:

```

 ___________           ___________           __________          _________
|           |         |           |         |          |        |         |
|   INPUT   |  --->   |  LAYER_0  |  --->   | LAYER_1  | ---->  | OUTPUT  |
|___________|         |___________|         |__________|        |_________|

```

где LAYER_0 и LAYER_1 - скрытые слои

* I этап: input_data, size = 1 * 784
* II этап: weights_0, size = 784 * 400    -   первая матрица весов
* III этап: layer_0, size = 1 * 400       -   первый скрытый слой
* IV этап: weights_1, size = 400 * 100    -   вторая матрица весов
* V этап: layer_1, size = 1 * 100         -   второй скрытый слой
* VI этап: weights_2, size = 100 * 10     -   третья матрица весов
* VII этап: output, size = 1 * 10         -   10 цифр на выходе
